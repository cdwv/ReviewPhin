Plan 05 · repository rules

Give ReviewPhin its own instructions and skills.

Teams need a committed directory for review guidance and reusable skills. Copilot should load these through its existing mechanisms while continuing to load the repository's shared instructions.

Importance / effortMedium / Medium
Who noticesRepository teams
Main code areaWorkspace and model sessions
New stored dataNone
Finished result: a dedicated ReviewPhin directory supports familiar agent-instruction and skill formats on GitHub and GitLab. Existing instructions continue to reach reviews and replies that have a repository workspace.

What is wrong today?

  • ReviewPhin already makes common repository instructions available to Copilot, but does not register a directory dedicated to ReviewPhin.
  • The SDK loads modular rules and skills from additional directories. The dedicated main instruction file needs an additive system message.
  • Learned project memory and committed review rules serve different purposes. Both should remain available with their source clear.
Verified on September 12, 2026: a local dummy model endpoint received both root agent instructions and GitHub Copilot instructions with configuration discovery enabled, disabled, or omitted. Explicitly skipping custom instructions removed both. A custom model URL did not prevent instruction loading.

The implementation now has a loopback compatibility test for both OpenAI wire formats, selected review roles and reply sessions. It verifies shared and dedicated instructions, native skill activation and reference reads. Narrow path rules did not reliably activate and remain outside the supported scope.

What do we want instead?

Instructions

Use familiar file formats

Support a main agent-instruction file and optional modular rules in the dedicated directory. Repository-wide rules are supported; path-specific enforcement remains separate work.

Skills

Make review skills available

Support skill folders and their reference files. Skills should be available to the review roles and repository-backed replies through Copilot's native loading behavior.

  • Keep the repository root as the model session's working directory.
  • Add dedicated sources without overwriting shared instructions or changing reviewed files.
  • Use files from the exact reviewed commit across repository checkout, archive and targeted-file hydration.
  • Use the same behavior with Copilot subscription models and custom model endpoints.
  • A missing dedicated directory preserves current session behavior. Sessions without a repository workspace do not search the worker's directory for project rules.

Separate work: review-depth budgets, configuration or comment commands for choosing named skills, ReviewPhin-enforced matching against only changed files, and discovery of repository-defined agents. Native skill availability is included here; a new skill-selection interface is not.

How do we fix it?

1. Verify native loadingCapture requests and inspect available skills using the bundled CLI and a synthetic repository.
2. Hydrate the filesBring the dedicated directory and supported reference files into the existing workspace at the reviewed commit.
3. Register extra sourcesPass additional directories to the shared model session and confirm existing sources still load.

Compatibility boundaries

Instruction loading and broad configuration discovery are separate. Append the main file through an additive system message and register modular-rule directories directly. Enable only the skill support needed for explicit skill directories after checking its behavior. Do not turn on discovery of unrelated repository agents, plugins, hooks or external tools as a shortcut.

Keep ReviewPhin's existing review roles and read-only tool permissions. A skill may provide guidance and reference material; it does not grant permission to run scripts or add tools. Confirm that each review role can actually load skill content with the tools it has.

Conflicting guidance

Use Copilot's existing combination of shared and dedicated instructions. Do not promise that adding a directory establishes a new precedence order. Keep memory labeled as learned guidance and preserve the existing treatment of the triggering request. A guaranteed rule that committed guidance overrides memory needs a separately tested prompt policy.

File handling: define supported reference files, size and file-count limits, and encoding before implementation. Reject paths or links that escape the workspace. Report invalid or skipped sources clearly. Record discovered and configured sources separately from sources proven to have loaded.

Work steps

  1. Extend the compatibility probe. Test extra directories, existing sources, path matching, skills and selected review agents. Capture synthetic requests at a local endpoint so instruction delivery can be checked without paid model calls.
  2. Confirm the directory contract. Prefer standard agent-instruction and skill formats. Verify recursive rules, relative references and path-pattern resolution before documenting the supported layout.
  3. Extend workspace hydration. Use shared path rules for both platforms. Include targeted-file fallback and the reference files needed by supported instructions and skills.
  4. Wire the shared session. Register extra directories for reviews and repository-backed replies. Leave workspace-free sessions unchanged. Make skill activation work within existing role and permission boundaries.
  5. Document and expose the result. Record safe source metadata in run artifacts. Explain layouts, native path behavior, skill availability, memory conflicts and skipped-file behavior. Do not store instruction text in new database fields.

  • Use uppercase AGENTS.md for case-sensitive workers. The earlier .reviewphin/instructions.md proposal was not implemented; do not add an alias without a concrete need.
  • Shared session creation is the integration point for instructionDirectories, skillDirectories and, if needed, explicit enableSkills. Keep workingDirectory at the hydrated repository root. Prefer absolute, session-local paths; do not mutate process-wide environment variables.
  • The September 12 probe used @github/copilot-sdk 1.0.13, bundled CLI 1.0.83, and a loopback OpenAI-compatible Chat Completions endpoint. Both ordinary instruction markers were present for enableConfigDiscovery false, true and omitted, and absent with skipCustomInstructions: true. The committed CLI regression fixture now covers extra directories, selected roles, skills and references over both OpenAI wire formats.
  • Existing instruction paths, GitLab hydration and GitHub hydration must retain current behavior. GitLab's targeted-file fallback currently fetches root instructions and the GitHub instructions directory; include supported dedicated sources and references.
  • The bundled CLI loads recursive *.instructions.md through instructionDirectories, but omits a direct .reviewphin/AGENTS.md there and through the custom-instruction environment variable. Read that one file and use systemMessage: { mode: "append" }. Shared instructions stay intact. Use applyTo: "**" for supported modular rules. Narrow patterns did not activate reliably after view in the probe; no new glob matcher is included.
  • Review agent definitions and Reply sessions constrain tools and roles. Verify skill catalog visibility and actual SKILL.md delivery separately for review-author, context-analyst and chatter. Do not assume skill content is inherited by subagents or eagerly load every skill as a workaround. Establish native activation within existing read-only permissions before finalizing scope.
  • Keep enableConfigDiscovery behavior unchanged in this feature. A provider-specific cleanup is optional separate work, not a prerequisite for instruction directories. Set enableSkills: true only when dedicated skills exist, and add the native skill tool to the session and review-role allowlists. The compatibility test checks that unrelated repository skills and shell tools remain unavailable.
  • Do not replace the system prompt, rewrite root instructions, relocate the workspace into .reviewphin, or register repository agents over ReviewPhin's own roles.
  • Sources: native instruction conventions, SDK skills, instruction versus agent discovery, and reported interaction with explicit custom agents. Use installed types and runtime observations when upstream descriptions differ.

How do we know it works?

  • Requests contain both existing shared instructions and dedicated instructions. No dedicated directory gives the same behavior as before.
  • Repository-wide modular rules reach the request. Unrelated narrow rules do not leak into it. Narrow matching is documented as unsupported in this first release.
  • Each supported review role and repository-backed reply can discover and activate a sample skill, with content and reference material actually delivered. Existing roles and tool restrictions remain intact.
  • Files come from the reviewed commit on both platforms, including archive and targeted-file fallbacks. A rule changed in the review uses that commit's version.
  • Copilot subscription configuration and custom-provider configuration pass session-wiring tests. Synthetic provider requests cover both supported OpenAI wire formats; exercise a subscription session where test credentials are available.
  • Workspace-free sessions do not acquire project instructions or skills. Registering the dedicated directory does not activate unrelated repository configuration.
  • Missing, oversized, malformed, duplicate and unsafe sources have explicit tested outcomes. Run artifacts distinguish configured sources from observed loading; normal logs omit instruction contents.
  • No storage schema change is required. Memory and trigger guidance remain labeled and retain their existing handling.

Checks to run: targeted workspace, platform-runtime, harness-session, reviewer, chatter and prompt tests; the local CLI compatibility fixture; type checking and the application build. Exact commands are in the technical notes.
